- The `useLocalStorage` hook’s setter **must be typed as `Dispatch<SetStateAction<T>>`** (not just `(value: T) => void`) so that functional updaters like `setTabs(prev => ...)` are accepted.
- Any helper function used inside `useState` initialisers must be defined **before** the state declarations to avoid TDZ errors.

#### 12 Core Functionalities (exact requirements)
1. Responsive UI with dark mode toggle (saved to localStorage).  
2. HTTP method dropdown: GET, POST, PUT, PATCH, DELETE.  
3. URL input with pre‑send validation (non‑empty, valid HTTP/HTTPS). Show error and block send.  
4. Key‑value list for query parameters; editing must automatically update the URL field.  
5. Key‑value list for request headers.  
6. Raw body editor (textarea) accepting text or JSON; for POST/PUT/PATCH it is sent as request body.  
7. Response area showing HTTP status code (colored badge) and the response text.  
8. Error management: network errors, invalid URL, server unreachable – displayed as user‑friendly messages.  
9. “Clear All” button resets method, URL, params, headers, body to defaults.  
10. Request history saved to localStorage (max 100); collections saved to localStorage; both persist across sessions.  
11. Export collections to a JSON file, import from a valid JSON file.  
12. Multi‑tab support: each tab has its own method, URL, params, headers, body. Tabs can be added, closed, renamed.
